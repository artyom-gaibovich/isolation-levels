# Феномен (Phenomenon)

## Что такое феномен?

**Феномен** — это некоторая критическая или незапланированная ситуация, при которой:

- одна транзакция **видит изменения** из другой транзакции, или
- **бизнес-логика ломается**, потому что две транзакции, выполняясь параллельно, портят ожидаемый результат

## Суть проблемы

Две транзакции выполняются **параллельно**, тогда как логика программы рассчитана на **последовательное** выполнение. В итоге результат оказывается:

- полностью испорченным,
- частично испорченным,
- или нормальным — если параллельная видимость данных допустима для конкретной задачи.

> Всё зависит от **бизнес-логики** и текущей задачи. Нужно смотреть именно под задачу.

## Схема возникновения феномена

```
Транзакция 1          База данных          Транзакция 2
     |                     |                    |
     |--- изменяет данные ->|                    |
     |   (временно, не      |                    |
     |    персистировано)   |                    |
     |                     |<-- читает данные ---|
     |                     |   (получает         |
     |                     |    временные         |
     |                     |    изменения T1)     |
```

- **Данные в базе** — лежат постоянно
- **Временно изменённые данные** — хранятся в рамках конкретной транзакции, ещё не сохранены (`persist`) в базу
- Вторая транзакция каким-то образом **видит** эти временные изменения первой транзакции

## Пример

1. Транзакция 1 изменила какую-то запись (ячейку/рекорд) — изменение временное, ещё не закоммичено
2. Транзакция 2 считывает эти данные и **получает временное значение**
3. Транзакция 2 сохраняет это значение и продолжает работу с ним
4. Транзакция 1 в итоге может откатить изменения или изменить данные ещё раз

**Результат:** Транзакция 2 работала с данными, которые в итоге не существуют (или были изменены). Приведёт ли это к ошибке — **зависит от логики приложения**.
