# 10. Phantom Read (Фантомное чтение)

## Что такое Phantom Read

**Phantom Read** (фантомное чтение) — это аномалия транзакций, при которой:
- Транзакция дважды читает один и тот же **диапазон строк** по условию (`SELECT WHERE`)
- Между двумя чтениями параллельная транзакция **добавляет или удаляет** строку
- При повторном чтении транзакция получает **неожиданное количество строк** — отличное от первого чтения

Ключевое отличие от других аномалий: **сами данные не меняются** (нет UPDATE), но **состав набора строк меняется** из-за INSERT или DELETE.

## Механизм возникновения

Даже если транзакция залочила уже прочитанные строки — это не помогает:
- Лок стоит на **существующих** строках
- Новую строку, которую ещё не существовало, залочить заранее невозможно
- Параллельная транзакция вставляет новую строку рядом — и лок на неё уже не действует

## Примеры

### Пример 1 — INSERT (добавление строки)

| Транзакция 1 | Транзакция 2 |
|---|---|
| `SELECT WHERE amount >= 1000` → получает **V1, V2** (2 строки) | |
| *(выполняет какие-то задачи)* | `INSERT` нового значения **V3**, `COMMIT` |
| `SELECT WHERE amount >= 1000` → получает **V1, V2, V3** (3 строки) | |

Результат: при повторном чтении появилась **неожиданная новая строка** (`unexpected new row after the second read`).

### Пример 2 — DELETE (удаление строки)

| Транзакция 1 | Транзакция 2 |
|---|---|
| `SELECT WHERE ...` → получает **V1, V2** (2 строки) | |
| *(выполняет задачи)* | `DELETE` строки **V2**, `COMMIT` |
| `SELECT WHERE ...` → получает только **V1** (1 строка) | |

Результат: при повторном чтении одна строка **исчезла**.

## Когда это проблема

Аномалия важна, когда бизнес-логика рассчитывает на то, что:
- первое и второе чтение вернут **одинаковый набор строк**
- появление новой строки или исчезновение существующей **ломает логику**

Если такого требования нет — аномалия не критична. Но в сложных запросах к базе данных это может **незаметно поломать бизнес-логику**.

## Уровни изоляции и Phantom Read

- Некоторые уровни изоляции созданы для того, чтобы **отлавливать такие изменения** и предотвращать их
- Однако **не все уровни** с этим справляются
- Даже транзакция **самого высшего уровня** изоляции может не обнаружить баг, который испортит данные через логическую бизнес-ошибку
