# Dirty Read (Грязное чтение)

## Что такое Dirty Read?

**Dirty Read** (также называется **Write-Read конфликт**) — это аномалия, при которой одна транзакция читает данные, изменённые другой транзакцией, которая ещё **не выполнила `COMMIT`**.

То есть одна транзакция видит **все временные изменения** другой транзакции — даже незафиксированные.

## Как это происходит — схема

```
Транзакция 1              База данных         Транзакция 2
     |                         |                   |
     |--- читает данные ------->|                   |
     |                         |                   |
     |--- изменяет данные ----->|  (временно, без   |
     |    (без commit/rollback) |   commit)         |
     |                         |<-- читает данные --|
     |                         |   (получает        |
     |                         |    временные T1!)  |
     |--- ROLLBACK ----------->|                   |
     |   (данные откатились)   |                   |
     |                         |   Транзакция 2    |
     |                         |   не знает об     |
     |                         |   ROLLBACK и      |
     |                         |   использует      |
     |                         |   невалидные      |
     |                         |   данные          |
```

## Пример с конкретными значениями

| Шаг | Транзакция 1 | Транзакция 2 |
|-----|-------------|-------------|
| 1 | Читает значение: `10` (version 1) | |
| 2 | Обновляет значение до `20` (version 2) | |
| 3 | | Читает значение: получает `20` (временное!) |
| 4 | `ROLLBACK` → значение снова `10` | |
| 5 | | Не знает о rollback, продолжает использовать `20` |

**Итог:** Транзакция 2 работает с данными `20`, которые фактически **не существуют** в базе — они были откатаны.

## Последствия

- Бизнес-логика транзакции 2 принимает решения на основе **невалидных данных**
- Может привести к **рандомным и непредсказуемым последствиям**
- Транзакция 2 **doesn't know about rollback and uses invalid data**

## Когда Dirty Read может быть допустим?

В некоторых случаях это не критично, например:
- Если транзакция выполняет **только чтение** для статистики
- Если точность данных в данный момент не важна, и данные будут запрошены повторно при необходимости

## Dirty Read в PostgreSQL

- **Dirty Read** — это **аномалия**, а не уровень транзакции
- В PostgreSQL **Dirty Read запрещён по умолчанию**
- Дефолтный уровень изоляции в PostgreSQL — **`READ COMMITTED`**, который не допускает грязного чтения
- Даже самые первые (низкие) уровни транзакций в Postgres запрещают эту аномалию
