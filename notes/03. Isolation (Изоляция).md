# Изоляция (Isolation)

## Что такое изоляция?

**Изоляция** — это свойство из ACID, которое определяет, каким образом транзакции **влияют друг на друга** (аффектят друг друга).

База данных постоянно беспокоится о **консистентности данных**, и изоляция — один из инструментов, с помощью которого она это обеспечивает.

## Компромисс: производительность vs надёжность

При выборе уровня изоляции всегда есть компромисс:

- **Максимальная производительность (performance)** — транзакции меньше изолированы, больше видят друг друга
- **Максимальная надёжность (reliability)** — транзакции полностью изолированы, но это дороже по ресурсам

## Как работает изоляция на уровне хранилища

### Собственная копия данных для каждой транзакции

Когда транзакция изменяет данные, база данных создаёт **отдельную копию** этих данных — именно для этой транзакции.

В **PostgreSQL** это реализовано следующим образом:
- Изменённые записи хранятся **в той же таблице** — рядом с оригинальными
- Каждая такая копия **помечается** специальными флажками / идентификаторами транзакции
- По этим меткам база данных всегда понимает, какие значения были изменены в рамках какой транзакции

```
Таблица:
┌──────────────────────────────────────────┐
│  [original row]                           │
│  [modified row] ← txn_id = T1 (T1 видит) │
│  [modified row] ← txn_id = T2 (T2 видит) │
└──────────────────────────────────────────┘
```

### Барьер изоляции

Изоляцию можно представить в виде **барьера** между транзакциями:

- Транзакция **T1** изменила данные (помечены зелёным/оранжевым)
- Транзакция **T2** хочет увидеть, были ли эти данные изменены — но **не может**, барьер не пускает
- Аналогично, **T1** не может увидеть изменения **T2**

Каждая транзакция работает как будто **в полной изоляции** от остальных.

## Аналогия с потоками (threads)

Каждую транзакцию можно представить как **отдельный поток (thread)**:

- Потоки выполняются **параллельно**
- В каждом потоке есть **свой стек** — свои локальные изменения
- Никто снаружи не видит, что происходит внутри потока, пока он не завершился

## Управление уровнями изоляции

Барьер изоляции можно **настраивать** — разрешать или запрещать транзакциям видеть изменения друг друга:

- **Запретить** — транзакция ничего не видит из чужих изменений (максимальная изоляция)
- **Разрешить** — транзакция может видеть часть или все изменения других транзакций (меньше изоляции, больше производительности)

Конкретные правила видимости определяются **уровнями изоляции**, которые рассматриваются далее.
